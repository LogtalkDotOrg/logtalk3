``decode/9``
^^^^^^^^^^^^

Decodes captured stdout and process metadata into a collected ``max_sat_result(Status, Model, Properties)`` term, mapping reported literals back through an optional ``Variables`` table. ``Status`` is one of ``optimal``, ``satisfiable`` (a best-known solution of an interrupted anytime run that was accepted because ``Anytime`` is ``true``), ``unsatisfiable``, and ``unknown``.

| **Compilation flags:**
|    ``static``

| **Template:**
|    ``decode(Solver,Codes,RawStatus,NormalizedStatus,Diagnostics,SourceMap,Variables,Anytime,Result)``
| **Mode and number of proofs:**
|    ``decode(+atom,+list(code),+term,+compound,+list(code),+list(compound),+term,+atom,-compound)`` - ``one_or_error``

| **Exceptions:**
|    ``Solver`` is not a ground term:
|        ``instantiation_error``
|    ``Solver`` is neither a variable nor an atom:
|        ``type_error(atom,Solver)``
|    ``Codes`` is a partial list or a list with an element ``Element`` which is a variable:
|        ``instantiation_error``
|    ``Codes`` is neither a partial list nor a list of character codes:
|        ``type_error(codes,Codes)``
|    ``Codes`` has no status line or an unsupported status label:
|        ``domain_error(max_sat_output,Field-Value)``
|    A witness literal number has no entry in the variable table:
|        ``domain_error(max_sat_output,variable(Number))``
|    ``NormalizedStatus`` is fatal or inconsistent with the decoded solver result:
|        ``domain_error(max_sat_process_status,NormalizedStatus)``
|    ``Variables`` is ground but neither ``none`` nor a list of pairs:
|        ``type_error(list(pair),Variables)``
