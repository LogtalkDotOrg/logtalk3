souffle

The souffle library provides access to the Souffle Datalog engine CLI, Datalog source generation, an opt-in object expansion hook, and collected result inspection (decoded .output relations and .printsize counts).

This library interacts with the Souffle CLI using the process library. Therefore, it currently supports ECLiPSe, GNU Prolog, SICStus Prolog, Shumway Prolog, SWI-Prolog, Trealla Prolog, and XVM.

Requirements

Solving requires the souffle executable, available on the system PATH or selected using the executable(Path) option. This library targets Souffle 2.5. Souffle is available from its official website. The compile(true) option additionally requires a working C++ toolchain (Souffle’s -c flag compiles the generated C++ program before running it).

On POSIX systems, solving also requires /bin/sh, with mktemp available on PATH. On Windows, solving requires PowerShell 7.3 or later (pwsh on the system PATH).

The bundled souffle_process.sh and souffle_process.ps1 launcher scripts must remain in the scripts subdirectory of the library.

API documentation

Open the ../../apis/library_index.html#souffle link in a web browser.

Loading

To load this library, load its loader.lgt file:

| ?- logtalk_load(souffle(loader)).

Testing

To test this library, load its tester.lgt file:

| ?- logtalk_load(souffle(tester)).

The tests include source-generation goldens, CSV/printsize decoding, expansion isolation and variable sharing, source/result accessors, and solving. Solver integration has been tested with Souffle 2.5 and verified against the installed CLI (exit codes, CSV formatting, aggregate syntax, and escaping). Solver tests are conditional on the availability of the souffle executable.

Problem fixtures are written as Logtalk objects implementing souffle_problem_protocol. The tester loads them with hook(souffle_expansion) and solves them using object(Object), checking conversion into Datalog source and complete CLI solving:

  • test_files/reachability.lgt defines souffle_reachability, the graph reachability example from the Souffle documentation, with edge as an .input relation and path as an .output/.printsize relation.

  • test_files/graph_stats.lgt defines souffle_graph_stats, covering typed columns (number, unsigned, float, symbol), negation (\+), comparisons, the count/sum/max/min/mean aggregates, and the cat/2 string-concatenation functor.

Problem sources

A Datalog problem can be represented in several ways:

  • file(Path): Path must be an atom identifying a native Datalog file.

  • codes(Codes): Codes must be a list of character codes representing native Datalog source.

  • terms(Statements): Statements must be an ordered list of canonical ground terms representing the problem.

  • object(Object): Object must be an object containing the problem and implementing souffle_problem_protocol.

The main library predicates take a ground problem source as an input argument.

Usage

Load the library, then compile an object defining a Datalog problem using the souffle_expansion hook. For example:

| ?- logtalk_load(souffle(loader)),
     logtalk_load(souffle('test_files/reachability'), [hook(souffle_expansion)]).

To inspect the generated Datalog source without running Souffle, use the souffle::program/1 predicate:

| ?- souffle::program(object(souffle_reachability)).

Use the souffle::solve/3 predicate to solve the problem. The outputs/1 option is always required to decode .output relations: it lists which relations to read back and their column types, since tab-separated CSV output carries no embedded type information. For example:

| ?- souffle::solve(
         object(souffle_reachability),
         Result,
         [facts_data([edge-[[1,2],[2,3]]]), outputs([path-[number,number]])]
     ),
     souffle::relation(Result, path, _, Rows).

In alternative, a Logtalk application can instead dynamically build a list of canonical statements and solve them through the terms(Statements) source, without defining an object or loading the hook. An example using a trivial single-fact program:

| ?- souffle::solve(terms([
         decl(edge, [x-number, y-number]),
         fact(function(edge, [number(1), number(2)])),
         output(edge)
     ]), Result, [outputs([edge-[number,number]])]),
     souffle::relation(Result, edge, _, Rows).

The program/2 predicate returns Datalog character codes without invoking Souffle. Native Datalog sources pass through unchanged; Souffle parses and reports any errors directly.

See the next section for full details on the options.

Solving

The public source and result predicates are declared in the souffle_protocol protocol. The object data-provider interface is declared in the souffle_problem_protocol protocol. The serializer, CSV/printsize decoder, and expansion hook document their interfaces in their respective source files.

The solve/2 predicate solves a source with default options. The solve/3 predicate accepts an explicit final options list. Both predicates return a ground collected result after subprocess completion and resource cleanup.

The supported options are:

  • executable(Path) selects a single executable, not a shell command line. When omitted, the executable name is souffle, resolved through PATH. Existing executable paths are used directly.

  • jobs(Count) selects a positive parallelism degree or auto; the default is 1.

  • warnings(Bool) disables Souffle warnings (-w) when false; the default is true.

  • compile(Bool) compiles the generated C++ program before running it (-c) when true; the default is false (interpreter mode).

  • facts(Path) selects an existing external directory of .facts files, passed directly as the Souffle fact directory; the default is none.

  • facts_data(Pairs) supplies Relation-Rows pairs (Rows a list of row value lists; integers, floats, and atoms for number/unsigned, float, and symbol columns respectively), materialized as .facts files in an owned temporary directory; the default is []. facts/1 and facts_data/1 are mutually exclusive: supplying both with non-default values raises domain_error(souffle_facts_option, ...).

  • outputs(Pairs) supplies Relation-Types pairs (Types a list of column type atoms, one of number, unsigned, float, or symbol) listing which .output relations to decode and their column types; the default is [] (nothing decoded). This option is always required, regardless of source kind, since tab-separated CSV output carries no embedded type information.

  • printsizes(Names) supplies relation names whose .printsize count to decode from captured stdout; the default is [].

Shared options semantics apply: repeated options are accepted and the first occurrence wins.

A declared .input relation with no matching .facts file (neither supplied via facts/1/facts_data/1 nor otherwise present in the fact directory) is silently treated as an empty relation only if that relation is otherwise unused (not read by any rule or .output). If a rule actually reads it, a missing .facts file is a Souffle error (surfaced as souffle_solver_error/4), not an empty relation. This is Souffle’s own behavior, not a limitation of this library.

Generated Datalog source is written using UTF-8. Existing native source files are left untouched. Temporary input, fact, and output files and directories created for solving are removed before returning the result.

Shell dependencies that cannot be resolved raise an existence error. Launcher failures raise souffle_transport(Stage, Status, Details) errors. Invalid CSV content, a missing requested relation file, and a nonzero Souffle exit status raise souffle_solver_error(Formal, Status, Diagnostics, SourceMap) errors, retaining the captured diagnostics and object source map.

Statement vocabulary

A Datalog program can be built in one of two equivalent ways:

  • Write an object implementing souffle_problem_protocol, loaded with hook(souffle_expansion), using ordinary directives, facts, and rules (as in test_files/reachability.lgt and test_files/graph_stats.lgt). The hook translates each directive, fact, and rule into one canonical statement.

  • Supply the canonical statements directly as a terms(Statements) source, bypassing the expansion hook entirely.

Both paths produce the same canonical statements, serialized by the souffle_program object.

Directives

Each directive recognized by souffle_expansion has the same functor and arity as its canonical statement; the directive is just that statement written as a :- directive instead of a list element:

Directive

Canonical statement

Meaning

:- decl(Name, Columns)

decl(Name, Columns)

a .decl declaration; Columns a list of ColumnName-Type pairs (Type one of number, unsigned, float, symbol)

:- input(Name)

input(Name)

a .input directive

:- output(Name)

output(Name)

a .output directive

:- printsize(Name)

printsize(Name)

a .printsize directive

:- raw(Source)

raw(Codes)

trusted raw Datalog source text, passed through unchanged (Source normalized to Codes)

:- comment(Source)

comment(Codes)

a // line comment (Source normalized to Codes)

For example, test_files/reachability.lgt writes:

:- decl(edge, [x-number, y-number]).
:- input(edge).

which the hook turns into the canonical statements decl(edge, [x-number, y-number]) and input(edge).

Facts and rules

Ordinary Prolog-like facts and rules have no directive form: they are translated directly into fact(Atom) and rule(Head, Body) canonical statements, where Atom/Head is a function(Name, Arguments) term and Body is a list of literals. For example, the rules in test_files/reachability.lgt:

path(X, Y) :- edge(X, Y).
path(X, Y) :- path(X, Z), edge(Z, Y).

translate into:

rule(function(path, [variable('X'), variable('Y')]), [
    function(edge, [variable('X'), variable('Y')])
])
rule(function(path, [variable('X'), variable('Y')]), [
    function(path, [variable('X'), variable('Z')]),
    function(edge, [variable('Z'), variable('Y')])
])

A bare fact, such as edge(1, 2). in test_files/graph_stats.lgt, translates into fact(function(edge, [number(1), number(2)])).

Body literals other than a positive function(Name, Arguments) atom are:

  • not(Atom), from a \+ goal, for negation. For example, test_files/graph_stats.lgt’s \+ edge(X, _) translates into not(function(edge, [variable('X'), anonymous])).

  • compare(Operator, Left, Right), from a =, \=, <, =<, >, or >= goal, for =, !=, <, <=, >, >= comparisons. Either operand can be an aggregate(Function, TargetExpr, Body) term, written as aggregate(Function, Target, Body) (Target a variable, a term, or none; Function one of count, sum, max, min, mean). For example, test_files/graph_stats.lgt’s X = aggregate(count, none, [edge(_, _)]) translates into compare('=', variable('X'), aggregate(count, none, [function(edge, [anonymous, anonymous])])). The mean aggregate requires its target expression to already resolve to a float-typed value; Souffle does not implicitly widen number to float for mean.

Term arguments, used both as function arguments and as aggregate targets, are: number(Integer), unsigned(Integer), float(Float), string(Codes) (a quoted symbol literal), variable(Name), anonymous, arithmetic(Operator, [Left, Right]) for +, -, *, /, %, and cat(Left, Right) (the built-in string-concatenation functor, written directly as cat(Left, Right) in a clause body or argument position).

Known limitations

  • No custom .type declarations (type aliases, records, unions, or ADTs); column types are restricted to the four Souffle primitives.

  • No components, choice construct, subsumption, user-defined functors, provenance (-t), profiling (-p), debug reports (-r), SQLite or stdin I/O, compressed or RFC 4180 CSV I/O, per-relation custom filename/delimiter overrides, or the legacy input/output qualifier syntax.

  • No .limitsize directive and no solver-native time limit: Souffle has no CLI time-limit flag; impose one externally (for example, at the operating-system level) if needed.

  • Souffle’s default (non RFC 4180) tab-separated CSV output does not escape symbol values at all: a symbol value containing a literal tab byte breaks column alignment on decoding. Avoid such data, or post-process affected columns externally.
